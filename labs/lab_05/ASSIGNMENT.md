# Лабораторная работа № 5

## Расчёт метрик и подготовка данных для анализа

Продолжите свой проект после ЛР № 4. Рассчитайте метрики на готовой витрине,
проверьте полученные числа и подготовьте данные для дальнейшего анализа.
В ЛР № 7 вы продолжите работу **в этом же ноутбуке**, добавив графики и визуальный отчёт.

Подключение к данным и примеры SQL можно взять из демо и адаптировать к своему проекту.

## Что нужно подготовить

- Ноутбук `notebooks/calculate_metrics.ipynb` с SQL, результатами и проверками.
- Короткое описание выполненной работы в `docs/metrics.md`.

В ноутбуке нужны код, SQL и сохранённые результаты выполнения. Все описания,
обоснования и вывод запишите в `docs/metrics.md`. SQL и полные таблицы в этот
документ копировать не нужно.

Markdown-ячейки демо помогают разобраться в работе. Их можно сохранить как подсказки,
но переносить или дописывать такие ячейки для сдачи не требуется.

Подготовьте в памяти ноутбука три результата:

| Результат                   | Что в нём находится                                                                  | Для чего понадобится в ЛР № 7                  |
|-----------------------------|--------------------------------------------------------------------------------------|------------------------------------------------|
| Основная группировка        | Метрики по категориям, часам или другим группам                                   | Сравнить значения на графиках                  |
| Уточняющая группировка      | Те же метрики с дополнительным признаком, например по категории и району          | Проверить общую картину внутри отдельных групп |
| Отдельные числовые значения | Значения одного признака для распределения или двух признаков для исследования связи | Построить распределение или показать связь     |

На выходе - временные таблицы DuckDB.
Сохранять отдельные файлы с промежуточными данными не требуется.

## Порядок работы

### 1. Выберите вопрос и метрики

Возьмите **один вопрос** из своего `Project Brief` и не менее **двух разных метрик**,
которые помогают на него ответить. Например, количество заказов и среднее время выполнения.
Одна метрика, посчитанная для разных групп, не считается двумя разными метриками.

В `docs/metrics.md` укажите вопрос, путь к витрине и период или снимок данных.
Кратко запишите, что означает одна строка витрины.

Для каждой метрики запишите там же:

- Что она измеряет.
- Как рассчитывается.
- Какие записи и значения участвуют в расчёте.

Используйте решения о качестве из предыдущих работ. Например, отрицательная сумма
может исключаться из средней стоимости, но сама запись при этом остаётся в подсчёте
поездок.

### 2. Рассчитайте общий итог и метрики по группам

Напишите SQL для общего итога, затем рассчитайте метрики по выбранным группам.
Например, сначала по всем поездкам, затем по часам посадки.

Рядом с метриками выведите размер группы. Если среднее использует только часть
значений, покажите, сколько значений в него вошло.

Используйте **одну оконную функцию**, которая помогает сравнению: например,
рассчитайте долю группы в общем количестве или место группы в рейтинге.
Объясните смысл результата в `docs/metrics.md`. Для доли предусмотрите случай
нулевого знаменателя в SQL.

### 3. Подготовьте уточнение и отдельные значения

Добавьте к группировке подходящий признак и рассчитайте те же метрики.
Например, сравнение по часам уточните по районам посадки. Эта таблица должна
помогать ответить на тот же вопрос, а не начинать новое исследование.

Отдельным запросом выберите числовые значения для будущего распределения или связи.
Например, получите длительность каждой поездки. Не пытайтесь восстановить
распределение из средних или медиан групп. В описании выборки укажите, какие записи
в неё вошли.

Если в вашем наборе нет времени, используйте категории, территории или другие
подходящие признаки. Строить графики в этой работе пока не нужно.

Дайте результатам понятные имена и оставьте их доступными в памяти ноутбука.
В группировках должны быть признаки групп, метрики, размеры групп и необходимые
знаменатели. В основной группировке сохраните также результат оконной функции.

### 4. Проверьте полученные числа

Выполните **не менее двух проверок**, подходящих вашим расчётам. Например:

- Сумма количества записей по группам совпадает с общим итогом.
- Число значений в среднем совпадает с отдельным подсчётом подходящих значений.
- Доли всех непересекающихся групп вместе дают 100 % с учётом округления.
- Число отдельных значений соответствует числу записей, выбранных для этого расчёта.

Выполните проверочные запросы в ноутбуке и сохраните результаты. В `docs/metrics.md`
кратко укажите для каждой проверки, что проверяли, что ожидали и что получили.
Если числа не сходятся, найдите причину.

Помните: общее среднее нельзя получать простым усреднением средних групп разного
размера. Медиану нужно пересчитать по исходным значениям. Пропуск значения
и известный ноль также могут по-разному влиять на расчёт.

### 5. Опишите результат и подготовьте сдачу

В `docs/metrics.md` опишите три подготовленных результата: их имена, содержимое,
смысл одной строки и назначение в дальнейшем анализе. Отметьте важные ограничения.
Вопрос, определения метрик и итоги проверок остаются в этом же документе.

Завершите `docs/metrics.md` коротким выводом: какое различие видно по числам, насколько велики
сравниваемые группы и какое ограничение нужно учитывать. Наблюдаемое различие
само по себе не объясняет его причину.

Перезапустите jupyter-ядро и выполните ноутбук сверху вниз. Убедитесь, что все результаты
создаются заново без ручного восстановления переменных. Сохраните ноутбук с актуальными
результатами выполнения.

Работайте в ветке `lab-05`. Сдайте Pull Request в `main` своего репозитория с ноутбуком
и документом `docs/metrics.md`.
